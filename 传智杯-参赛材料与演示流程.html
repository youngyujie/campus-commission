校园委托 —— 参赛材料清单与演示流程

一个面向校园的轻量任务委托平台（发单 · 接单 · 押金 · 验收 · 评价 · 仲裁），全程以「人与 AI 协作」的方式从零搭建并上线。本文档把赛道要求逐条拆解，并给出可直接照做的演示视频脚本与材料准备清单。

技术栈：uni-app + Vue 3 + Vite 构建：单文件 HTML / H5 后端：Node 原生 http + JSON 演示账号：林小满 / 许一帆 / 张老师

3演示视频流程（约 7 分 30 秒）

总时长控制在 5–8 分钟。建议 1080p 录屏 + 麦克风讲解；提前把演示账号数据准备好，避免现场卡顿。

00:00 – 00:20
开场：一句话讲清项目
画面：标题页 / 项目 Logo。台词：「这是『校园委托』，一个面向本校学生的小额互助平台——发一条委托，自由接单，押金保障，信用沉淀。它从零到上线，全程由我和 AI 协作完成。」
00:20 – 00:50
登录与账号体系
操作：打开线上链接 → 登录页 → 点演示账号「林小满」直接进入。台词：说明手机号/密码登录、演示账号、以及「认证学生才能发单接单」的规则。
00:50 – 01:50
电脑端大厅：导航联动是重点
操作：滚动页面 → 顶部吸顶导航变白/加阴影/变矮；滚到哪个分类，指示条就平滑滑到哪个标签；点标签，页面平滑滚到对应分区；鼠标悬停委托卡轻微上浮。台词：把「滚动联动」这个亮点讲透（这是最容易加分的交互细节）。
01:50 – 02:30
发布一条委托（核心业务）
操作：点「＋ 发布」→ 选类型（代取代买）→ 填标题/地点/报酬/截止 → 提交。台词：讲表单校验、报酬上限、押金规则、违规词拦截。
02:30 – 03:10
订单流转 + 个人中心
操作：进「我的订单」看状态（待接单→已接单→待验收→已完成）；进「我的」看立体卡片、按钮按下反馈。台词：讲完整闭环与交互质感。
03:10 – 03:50
手机端适配
操作：手机打开同一链接 → 底部悬浮胶囊导航、浅薄荷绿椭圆胶囊选中、卡片点按上浮。台词：讲双端一致、移动端导航的胶囊滑动。
03:50 – 05:50
AI 协同过程复现（≥2 分钟，评分关键）
详见 §4。这一段单独按脚本演，展示「你怎么提需求、AI 怎么给方案、你怎么约束、怎么修 Bug」。
05:50 – 06:40
技术架构速讲
操作：切到代码/架构图。台词：uni-app + Vue3 单文件构建、组件化、store 状态层、sync 同步层、Node 后端；强调「AI 生成代码后我用什么边界约束它」。
06:40 – 07:20
10 分钟极速复现
操作：git clone → npm install → npm run dev:h5 → 打开本地地址；或 npm run build:single 出单文件双击即开。台词：强调「零配置、可复现」。
07:20 – 07:30
收尾
台词：一句话总结「人定方向与边界，AI 负责落地，过程可追溯、结果可复现」。

4「AI 协同过程复现」段脚本（03:50 – 05:50）

赛道明确要求「至少 2 分钟」。建议用「一正一修」两段：一段展示用 Prompt 生成核心模块，一段展示引导 AI 修一个顽固 Bug。

4.1 用 Prompt 生成核心模块（约 70 秒）

屏幕展示：把下面这段 Prompt 原样输入 AI，然后展示 AI 返回的方案与生成的代码（hall.vue 的分类分区、滑动指示条、滚动联动逻辑）。

PROMPT · 大厅改版把大厅改成「分类分区 + 滚动联动」： 1）列表按分类分成多个区块，每个区块有标题和条数； 2）顶部是一条吸顶导航，分类标签下面有一条滑动指示条； 3）页面滚动到哪个区块，指示条就平滑滑到对应标签； 4）点击标签，页面平滑滚动到对应区块； 5）动效统一 ease-out、300ms，简约干净，禁止弹跳/回弹。 只用真实数据，不要改数据层。

讲解要点：你如何约束——「只改 pages/components、不动 utils/store.js」；AI 如何落地——它新建了 sections 分组、.topbar-ind 滑动条、updateActiveByScroll() 滚动联动、uni.pageScrollTo 点击滚动。

4.2 引导 AI 修一个顽固 Bug（约 50 秒）

屏幕展示：先演示 Bug（切到发布页导航消失、退出后导航点不动），再贴出下面这段「Bug 描述 Prompt」，然后展示 AI 的定位与修复。

PROMPT · Bug 修复发现两个 bug： 1）底部导航切到「发布」时，导航栏会消失； 2）从发布页退出后，底部导航卡住、点不动。 我要的效果：点发布时底部导航不消失；发布页的「发布订单」按钮原本固定在底部，现在要和其他内容一样随滚动移动；离开发布后导航也能正常点。

讲解要点（体现「引导」而非「甩锅」）：AI 先定位根因——发布页没有挂载底部导航组件，且导航内部有个「跳转中」的锁在 navigateTo 后没有复位，旧页面残留在栈里导致锁死。修复：给发布页补上导航、按钮改成随内容滚动、导航跳转统一用 reLaunch 并在回调里复位锁。最后现场验证「大厅↔发布↔我的」来回切换正常。

录制技巧：把 Prompt 用大字号贴出来、让观众看清「你输入了什么」；AI 返回后不要全屏滚代码，用鼠标圈出关键函数名（如 updateActiveByScroll、reLaunch），再口述一句「我为什么要这样约束它」。

5Prompt 历史快照（≥3 个核心迭代，可直接引用）

赛道要求「至少 3 个核心功能迭代的完整 Prompt 链」。以下 4 段来自本项目的真实协作过程，可直接作为快照文字，或对照它们去截图/录屏。

迭代 ① 统一主色（设计债清理）

我的 Prompt前端改造请先读 campus-commission/前端交接文档.md，严格按第 1 节的边界执行：只改 pages/ 和 components/ 的模板与样式，不动 utils/store.js 等数据层。

AI 的处理：先读交接文档定位到 §7.1「两套主色」的设计债；把登录/学生认证/头像裁剪三处的青绿（#48CBA8→#32AD8D）统一成蓝紫（#4C6FFF→#3A5BE0）；绿色插画在 utils/art.js（边界外）→ 新建 components/CampusBackdrop.vue 重绘蓝紫版替换，art.js 原封不动。

我如何引导修正：发现 mine.vue 里两处语义色（成功态的 mint 绿）被误改 → 要求回退，保留 mint 作为「成功/提示」语义色，不当作品牌色。

迭代 ② 导航动效规范落地

我的 Prompt电脑端导航动效参数：动画函数 ease-out，时长 280ms；侧边栏展开 width 平滑过渡；子菜单展开 max-height 过渡 + opacity 淡入；悬浮下划线 transform: scaleX 0→1；滚动导航 background-color 和 box-shadow 渐变、高度小幅过渡；禁止弹跳/回弹/过度放大，轻量化，适配 PC。手机端导航栏用立体椭圆和背景分离，参数一致。

AI 的处理：把参数抽成共享层（--dur:280ms + 统一 ease-out），四套皮肤只改视觉不改节奏；侧栏 width、子菜单 max-height+opacity、下划线 scaleX、吸顶栏 bg/shadow/height 全部按参数实现。

我如何引导修正：手机端粗野主义皮肤的激活图标黑字压黑底看不见 → 要求改成黄底黑字、对比清晰。

迭代 ③ 大厅照演示页重做 + 滚动联动

我的 Prompt将 ui 界面和动态效果全部实装到我的网站中，格式和这个动效规范演示一样，双端都按照这个来。（在追问中选定：整个大厅照演示重做）

AI 的处理：重写 hall.vue——顶栏「委托大厅 + 分类链接条（scaleX 悬停下划线）+ 信誉 + 头像 + 发布」、Hero、4 张统计卡、桌面扁平行/手机卡片，数据全部走真实 store。

我如何引导迭代：进一步要求「滚到哪个分类，指示条平滑移到哪个标签；点击标签平滑滚到对应位置」→ AI 增加 .topbar-ind 滑动指示条、onPageScroll 驱动的 updateActiveByScroll()、点击 uni.pageScrollTo，并处理「滚到底自动选最后一类」的边界。

迭代 ④ 顽固 Bug：发布页导航消失 / 卡死

我的 Prompt发现 bug：下方导航栏切换到发布时，导航栏会消失；并且退出发布页面后，下方导航栏卡住不能点击。修复 bug，我要的效果是：点发布时导航不消失；发布页原本置底的「发布订单」按钮改成随内容滚动；离开发布后导航也能正常使用。

AI 的定位：① 发布页没有挂载底部导航组件 → 切过去就没了；② 导航内部「跳转中」的锁在 navigateTo 后未复位，旧页面残留在栈里 → 退出后锁死。

修复：发布页补 <TabBar active="publish">；固定底栏改为内容内 .submit-inline（随滚动）；导航跳转统一 uni.reLaunch 并在 complete 里复位 navigating。验证「大厅↔发布↔我的」来回切换正常、0 报错。

710 分钟极速复现指南（可直接放进 README.md）

把下面内容粘到仓库 README.md 的「快速开始」里即可满足赛道要求。

环境要求

  • Node.js ≥ 22（推荐 22.x LTS），npm ≥ 10
  • 无需数据库、无需额外环境变量（前端默认走本地存储；后端可选）

三步跑起来

终端# 1. 安装依赖 npm install # 2. 本地开发（H5） npm run dev:h5 # 打开终端提示的本地地址（通常 http://localhost:5173） # 3. 或直接产出「单文件版」，双击即开、离线可用 npm run build:single # 生成：校园委托-单文件版.html

登录演示

打开后是登录页，点页面下方的演示账号 林小满 / 许一帆 / 张老师 即可直接进入（无需注册）。

可选：多人共享后端

终端cd server node server.js # 默认 http://localhost:3000，数据存 data.json # 部署到云服务器：sh deploy.sh（Ubuntu，systemd 托管，自带每日备份）

环境变量模板

前端无需环境变量；后端可选 PORT（默认 3000）。如需，提供 .env.example：

.env.example# 后端端口（可选，默认 3000） PORT=3000
