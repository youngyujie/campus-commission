## 迭代 ① 统一主色（清理设计债）

**背景**：项目早期登录页用了青绿主色，后来全站改成蓝紫，但登录/认证/裁剪三处没跟上，形成「两套主色」的设计债。

**我的 Prompt**
```
前端改造请先读 campus-commission/前端交接文档.md，
严格按第 1 节的边界执行：只改 pages/ 和 components/ 的模板与样式，
不动 utils/store.js 等数据层。
```

**AI 的处理**
- 先读交接文档，定位到 §7.1「两套主色（设计债，优先处理）」；
- 把登录、学生认证、头像裁剪三处的 `#48CBA8 → #32AD8D` 统一换成 `#4C6FFF → #3A5BE0`；
- 绿色校园插画在 `utils/art.js`（边界外），AI 没有动它，而是新建 `components/CampusBackdrop.vue`，把插画重绘成蓝紫版给登录页用。

**我如何引导修正**
- 发现 `mine.vue` 里「成功态」的薄荷绿（`#e6faf6 / #17977f`）被当成品牌绿一起改掉了 → 要求回退；
- 明确约定：**mint 是语义色（成功/提示），不是品牌色**，不应随品牌色统一。

## 迭代 ② 导航动效规范落地

**背景**：希望导航动效有一套统一、克制、不花哨的参数。

**我的 Prompt**
```
电脑端导航动效参数：
动画函数：ease-out，时长 280ms；
侧边栏展开：width 平滑过渡；
子菜单展开：max-height 过渡 + opacity 淡入；
悬浮下划线：transform: scaleX 0→1；
滚动导航：background-color 和 box-shadow 渐变过渡，高度小幅过渡；
禁止弹跳、回弹、过度放大效果，轻量化，适配 PC。
手机端导航栏用立体椭圆和背景分离，动效参数和电脑端一致。
```

**AI 的处理**
- 把参数抽成共享层（`--dur: 280ms` + 统一 ease-out），四套皮肤只改视觉不改节奏；
- 侧栏 width、子菜单 max-height + opacity、下划线 scaleX、吸顶栏 bg/shadow/height 全部按参数实现。

**我如何引导修正**
- 手机端粗野主义皮肤的激活图标「黑字压黑底」看不见 → 要求改成黄底黑字，提高对比度。

## 迭代 ③ 大厅照演示页重做 + 滚动联动

**背景**：把导航动效演示页的版式与效果，完整落到正式 App 的大厅。

**我的 Prompt（第一轮）**
```
将 ui 界面和动态效果全部实装到我的网站中，
格式和这个动效规范演示一样，双端都按照这个来。
```
（在追问中明确选择：**整个大厅照演示重做**，用真实数据。）

**我的 Prompt（第二轮，细化交互）**
```
帮我做导航栏效果：滚到哪个分类，指示条就平滑移到哪个标签；
点击标签平滑滚到对应位置。
```

**AI 的处理**
- 重写 `hall.vue`：顶栏「委托大厅 + 分类链接条（scaleX 悬停下划线）+ 信誉 + 头像 + 发布」、Hero、4 张统计卡、桌面双列卡片 / 手机卡片，数据全部走真实 store；
- 列表按分类分成 5 个 `.cat-section`；
- 增加单条滑动指示条 `.topbar-ind`（width + transform，300ms）；
- `onPageScroll` 驱动 `updateActiveByScroll()`：滚到哪个分区就激活对应标签；
- 点击标签用 `uni.pageScrollTo` 平滑滚到对应分区；
- 处理边界：滚到底部自动选中最后一个分类。

**我如何引导迭代**
- 第一版滚到底时最后两个标签点不亮 → 要求补「到底部自动选最后一类」的判断；
- 指示条太细看不清 → 要求加粗到 6rpx 并加投影。

## 迭代 ④ 顽固 Bug：发布页导航消失 / 卡死

**背景**：切换到「发布」页时底部导航消失，退出发布后导航点不动。

**我的 Prompt**
```
我发现了 bug：下方导航栏切换到发布时，导航栏会消失，
并且退出发布页面后，下方导航栏就卡住了不能点击。
修复 bug，我要的效果是：
点击发布的导航栏下方导航栏不会消失；
发布页原本是发布订单按钮置底不会随着屏幕移动，
现在我要他和发布页其他内容一样会随着用户的滑动而移动；
离开发布也导航栏也能正常使用。
```

**AI 的定位**
1. **发布页没有挂载底部导航组件** → 切过去导航就消失；
2. 导航内部有一个「跳转中」的锁（`navigating`），发布页用 `navigateTo` 打开后旧页面残留在栈里，这把锁没有复位 → 退出后导航锁死。

**AI 的修复**
- 发布页补上 `<TabBar v-if="!isDesktop" active="publish" />`；
- 去掉固定置底的 `.actionbar`，改为内容内的 `.submit-inline`（随内容滚动）；
- 导航跳转统一用 `uni.reLaunch`（销毁旧页），并在 `complete` 回调里复位 `navigating`；
- 验证：大厅 → 发布 → 大厅 → 我的，来回切换正常、0 报错。

**我如何验收**
- 让 AI 跑无头浏览器断言：发布页 `tabbar=true`、`actionbar=0`、`submit-inline` 的 `position=static`；连续切换页面后导航仍可点击。
