1项目概述

1.1 背景与定位

校园里存在大量小额、即时、非标准的互助需求：代取快递、代买饭、文档排版、临时拍照、占座等。它们金额小、频次高、信任半径短，用通用跑腿平台既不划算也不安全。「校园委托」面向同一所学校的学生，提供一个小额、有押金、有信用沉淀的委托闭环。

1.2 核心闭环

发布委托 → 自由接单 → 缴纳押金 → 交付 → 验收 → 评价 / 信用沉淀 → 纠纷仲裁。平台只做小额订单（报酬上限 200 元），押金不低于订单报酬、上限 200 元，验收后返还。

1.3 功能范围

模块主要内容
账号手机号/密码登录、学生认证、头像裁剪、信誉分
委托大厅分类分区、滚动联动导航、搜索、发布入口
发布类型/标题/地点/报酬/截止/附件、违规词拦截、押金规则
订单状态机（待接单→已接单→进行中→待验收→已完成/已取消）
消息 / 钱包私聊（限 10 句引导站内交易）、押金与收入
个人中心资料、技能标签、作品集、历史头像、立体卡片交互
管理后台审核委托、纠纷仲裁、分类与公告管理

2架构设计

2.1 技术栈与选型理由

层选型理由
视图uni-app + Vue 3一套代码同时产出 H5 与小程序，适合校园场景；Vue 3 组合式/选项式皆可
构建Vite 5启动快、构建快；通过自定义脚本把产物内联成单文件
状态自研 store.js轻量、无第三方依赖；用响应式 dataTick 驱动视图刷新
同步sync.js本地优先 + 增量推送 + 定时拉取版本号，弱网可用
后端Node 原生 http + data.json零依赖、单文件部署；几十人规模足够，运维成本极低

2.2 目录结构（节选）

campus-commission/
├─ src/
│  ├─ pages/            # 页面：login / hall / detail / publish / orders / chat / mine ...
│  ├─ components/       # 通用组件：TaskCard / SideNav / TabBar / AppHeader / Avatar ...
│  ├─ utils/            # 数据层：store.js / sync.js / seed.js / constants.js / api.js
│  ├─ App.vue           # 全局设计令牌与布局
│  └─ pages.json        # 路由与页面配置
├─ scripts/             # build-single.js（单文件构建）/ 自动化 flow 测试
├─ server/              # 可选后端：server.js + deploy.sh + data.json
└─ docs/                # 本文档、AI 协作记录、演示脚本

2.3 分层架构

整体是「视图层 → 组件层 → 状态层 → 同步层 → 后端」的单向数据流：

  • 视图层（pages）：只负责布局与交互，通过 store 暴露的函数读写数据，不直接碰存储。
  • 组件层（components）：可复用的展示与交互单元（委托卡、侧栏、底部导航、页头）。
  • 状态层（store.js）：内存状态 + 本地缓存，所有业务规则（押金、状态机、信誉）集中在这里，页面不重复实现。
  • 同步层（sync.js）：本地优先，操作后 300ms 增量推送；每 4 秒比对服务端版本号，变化则拉全量。
  • 后端（server.js）：单进程同时提供接口与网页，数据存 data.json，写入采用「先写临时文件再改名」防损坏。

2.4 两个关键设计

（1）单文件构建

scripts/build-single.js 以 UNI_SINGLE_FILE=1 关闭代码分割，再由 inline.js 把 JS/CSS 全部内联进一个 HTML。产物可双击打开、离线运行、静态托管，答辩演示零依赖。

（2）本地优先同步

打开页面先显示本地缓存（秒开），同时拉一次服务端数据覆盖；操作本地立刻生效，300ms 后把「变了哪几条」推给服务端；每 4 秒问一次版本号。推的是增量而非全量，流量小、弱网可用。

2.5 AI 生成代码的架构约束

AI 容易「越界」——把数据逻辑写进页面、把样式写死在各处。为约束它，项目确立三条硬边界，并在每次 Prompt 中重申：

  • 目录边界：前端改造只允许改 pages/ 与 components/，utils/ 数据层不动。
  • 设计令牌：颜色、圆角、阴影统一走 App.vue 里的 CSS 变量，禁止页面里散落魔法值。
  • 单一事实来源：业务规则只在 store.js 实现，页面只调用，不复制逻辑。
这三条边界让 AI 的产出「可预期」：即使它一次改很多文件，改动也局限在展示层，不会破坏数据与规则。

3意图控制策略（重点）

这一章回答赛道最关心的问题：我是如何设计上下文与 Prompt，让 AI 稳定产出我想要的结果的。

3.1 先给上下文，再给任务

每次大改前，先让 AI 读「交接文档」，把项目边界、设计系统、已知设计债讲清楚，再提需求。例如：

前端改造请先读 campus-commission/前端交接文档.md，
严格按第 1 节的边界执行：只改 pages/ 和 components/ 的模板与样式，
不动 utils/store.js 等数据层。

好处：AI 不会「热情过头」地去重构数据层，改动面可控，评审也能顺着文档复现。

3.2 Prompt 的四个要素

我把有效的 Prompt 拆成四块，缺一块就容易返工：

要素作用示例
目标一句话说清要什么「把大厅改成分类分区 + 滚动联动」
参数把模糊的「好看」变成可执行数值「ease-out，280ms；禁止弹跳/回弹/过度放大」
边界限定改动范围，防止误伤「只改 pages/components，不动数据层」
验收给出可自检的标准「滚到哪个分类指示条就滑到哪个标签；点标签平滑滚过去」

3.3 分步迭代，小步验收

不追求一次成型。每次只推进一个可验证的小目标：先统一配色 → 再抽导航动效参数 → 再做大厅版式 → 最后做滚动联动。每步做完立刻用无头浏览器截图/断言验收，通过了再进入下一步。这样即使某步跑偏，回退成本也很低。

3.4 失败模式与纠偏

失败模式现象我的纠偏
越界重构AI 顺手改了数据层Prompt 里重申目录边界，要求只提交展示层改动
语义色被误伤「成功态」的薄荷绿被当成品牌绿一起改掉明确「mint 是语义色，不是品牌色」，要求回退
动效过度按下反馈缩放 0.96、变暗 0.9，太重改成「轻微下压」：0.985 + 下沉 1px + 亮度 0.96
交互错位切到发布页导航消失、退出后卡死先让 AI 定位根因（缺组件 + 锁未复位），再按根因修
关键心得：AI 跑偏时，不要只说「不对，重做」，而要指出「哪里不对、为什么、期望是什么」。把 Bug 描述清楚（复现步骤 + 期望效果），AI 的定位准确率会高很多。

3.5 让 AI 自我约束的三个技巧

  1. 先读后写：要求它先读交接文档/相关文件，再动手，避免凭空发挥。
  2. 先定位再修：修 Bug 时要求它先给出根因分析，再改代码，避免「试错式乱改」。
  3. 给验收脚本：让它顺手写/跑一个断言（例如「点击后胶囊 translateX 应等于标签偏移」），用机器验证代替肉眼判断。

4可复现性论证

4.1 环境与依赖

项目要求
Node.js≥ 22（推荐 22.x LTS）
npm≥ 10
数据库不需要（前端本地存储；后端为单文件 JSON）
环境变量前端无需；后端仅可选 PORT

核心依赖：vue ^3.4.21、@dcloudio/uni-app、@dcloudio/vite-plugin-uni、vite ^5.2.8。全部通过 npm install 安装，无全局依赖。

4.2 一条命令跑起来

npm install
npm run dev:h5        # 本地开发，浏览器打开终端提示的地址
# 或
npm run build:single  # 生成「校园委托-单文件版.html」，双击即开

4.3 构建产物

单文件版把 HTML/CSS/JS 全部内联，零依赖、离线可运行，可直接静态托管（Netlify / Cloudflare Pages / 对象存储）或本地双击打开。

4.4 后端（可选）

cd server
node server.js        # http://localhost:3000，数据存 data.json
sh deploy.sh          # Ubuntu 一键部署（systemd 托管 + 每日备份）

4.5 演示数据

首次启动自动写入演示数据（11 条委托、7 个账号），登录页可直接点「林小满 / 许一帆 / 张老师」进入，无需注册，保证评审打开即用。

复现自检：首页不白屏 → 演示账号能进大厅 → 有委托列表与分类 → 能发布一条委托 → 手机端布局正常。

5AI 协作 Prompt 链（核心迭代）

以下四段来自真实开发过程，完整对话记录（截图/录屏）随仓库 docs/AI-协作记录.md 提供。

迭代 ① 统一主色（清理设计债）

【Prompt】前端改造请先读前端交接文档，严格按第 1 节边界：
只改 pages/ 和 components/ 的模板与样式，不动 utils/store.js。

AI 处理：定位到交接文档 §7.1「两套主色」；把登录/认证/裁剪的青绿统一为蓝紫；绿色插画在 utils/art.js（边界外），改为新建 CampusBackdrop.vue 重绘替换，原文件不动。

我如何纠偏：发现 mine.vue 把「成功态」的 mint 绿误改 → 要求回退，明确 mint 是语义色。

迭代 ② 导航动效规范落地

【Prompt】导航动效：ease-out / 280ms；侧栏 width 平滑过渡；
子菜单 max-height + opacity；下划线 scaleX 0→1；滚动导航 bg+shadow+height；
禁止弹跳/回弹/过度放大，轻量化，适配 PC；手机端立体椭圆同参数。

AI 处理：把参数抽成共享层，四套皮肤只改视觉不改节奏，逐项实现。

我如何纠偏：粗野主义皮肤激活图标黑压黑不可见 → 改黄底黑字提高对比。

迭代 ③ 大厅重做 + 滚动联动

【Prompt】将 UI 与动效全部实装到我的网站，格式和这个动效规范演示一样，
双端都按这个来。（追问中选定：整个大厅照演示重做）

AI 处理：重写 hall.vue：顶栏分类链接条（scaleX 下划线）+ Hero + 统计卡 + 双端列表，数据走真实 store。

我如何引导迭代：追加「滚到哪个分类指示条滑到哪个标签；点标签平滑滚过去」→ AI 增加滑动指示条、onPageScroll 驱动的滚动联动、uni.pageScrollTo 点击滚动，并处理「滚到底自动选最后一类」的边界。

迭代 ④ 顽固 Bug：发布页导航消失 / 卡死

【Prompt】Bug：切到发布时导航消失；退出发布后导航卡住点不动。
期望：点发布时导航不消失；发布页「发布订单」按钮改为随内容滚动；
离开发布后导航也能正常用。

AI 定位：① 发布页未挂载底部导航 → 消失；② 导航内部「跳转中」锁在 navigateTo 后未复位，旧页残留 → 锁死。

修复：发布页补 <TabBar>；固定底栏改为内容内 .submit-inline；跳转统一 reLaunch 并在 complete 复位锁。验证「大厅↔发布↔我的」来回切换正常。

6局限与展望

6.1 当前局限

  • 存储：后端为单文件 JSON + 内存，适合几十人演示规模，不适合高并发。
  • 鉴权：接口无服务端鉴权，拿到地址即可调用（校园演示定位，不放真实隐私）。
  • 同步：整份状态下发 + 增量推送，数据量变大后会变慢；并发改同一条为「后写覆盖」。

6.2 演进方向

  • 存储改为 SQLite，接口改为「按需查询」而非全量下发；
  • 引入服务端鉴权与会话，敏感操作二次校验；
  • 把押金、评价做成可审计的流水，便于纠纷追溯。

6.3 协作方法论沉淀

本项目验证了一套可复用的「人机协作」范式：人定方向与边界，AI 负责落地，机器断言负责验收。它不依赖某个特定 AI 工具，换一个模型，只要坚持「上下文 + 参数 + 边界 + 验收」四要素，产出依然稳定、可复现。
